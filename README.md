# for people — Telegram Mini App

Личная книга контактов с AI-поиском по интересам, психологическим портретом и т.д.
Этот проект — готовый к деплою React-сайт, который открывается внутри Telegram
как Mini App.

Если ты не программируешь — этот файл можно целиком отдать фрилансеру
как техническое задание. Всё нужное уже внутри проекта.

---

## Что уже сделано

- Дизайн и вся логика перенесены из прототипа в обычный React-проект (Vite)
- Хранение данных переключено с внутреннего механизма Claude на
  `Telegram.WebApp.CloudStorage` (см. `src/storage.js`), с fallback на
  `localStorage`, если открыть сайт в обычном браузере не через Telegram
- Вызов AI-помощника переписан так, чтобы API-ключ никогда не попадал
  в код фронтенда — вместо этого используется backend-прокси
  (пример готов в `api/ai-proxy.js`)

## Что нужно сделать разработчику (или тебе, по шагам ниже)

### 1. Установить зависимости и проверить, что всё работает локально

```
npm install
npm run dev
```

Откроется адрес вроде `http://localhost:5173` — в обычном браузере
приложение тоже откроется (просто будет использовать `localStorage`
вместо Telegram CloudStorage, это нормально для проверки).

### 2. Настроить AI-помощника (необязательно, но без этого шага кнопка
    "AI помощник" будет показывать сообщение "ещё не подключён")

AI не может стучаться в Anthropic API напрямую с телефона пользователя —
это небезопасно (ключ был бы виден всем). Поэтому нужен маленький backend.

Самый простой вариант — Vercel:

1. Получи API-ключ на console.anthropic.com
2. Задеплой проект на Vercel (см. шаг 3) — папка `api/` подхватится
   автоматически как serverless-функция
3. В настройках проекта на Vercel: **Settings → Environment Variables**
   → добавь `ANTHROPIC_API_KEY` = твой ключ
4. Скопируй `.env.example` в `.env`, впиши туда адрес:
   `VITE_AI_PROXY_URL=https://твой-проект.vercel.app/api/ai-proxy`
5. Пересобери проект (`npm run build`) и передеплой

Если AI-помощник не нужен вообще — можно просто не настраивать этот шаг,
остальное приложение будет работать полностью (контакты, категории,
теги, психологический портрет, импорт/экспорт CSV, массовое редактирование).

### 3. Задеплоить сайт (получить https-ссылку)

Проще всего — Vercel:

1. Зарегистрируйся на vercel.com (можно через GitHub)
2. Залей этот проект к себе на GitHub
3. На Vercel: **New Project** → выбери репозиторий → Deploy
4. После деплоя получишь ссылку вида `https://for-people-xxxx.vercel.app`

Обязательно должно быть **https** — Telegram не откроет обычный http-сайт.

### 4. Создать бота и подключить Mini App

1. Напиши в Telegram боту **@BotFather**
2. `/newbot` → придумай имя и юзернейм → получишь токен (сохрани его)
3. `/mybots` → выбери своего бота → **Bot Settings** → **Menu Button**
   → **Configure Menu Button** → вставь ссылку с шага 3
   (или через `/newapp`, если хочешь полноценный Mini App с иконкой
   в общем каталоге приложений Telegram)

### 5. Проверить

Открой бота в Telegram → нажми кнопку меню внизу экрана — приложение
откроется прямо внутри Telegram, с адаптацией под тему (тёмная/светлая)
и нативными жестами.

## Производительность (Модуль 2)

Проект разбит на модули, чтобы был возможен code-splitting и точечная мемоизация:

```
src/
├── constants.js          — MESSENGERS, категории по умолчанию, шаги формы и т.д.
├── helpers.js            — чистые функции (без состояния): парсинг CSV, маска телефона, ресайз фото
├── theme.js              — цвета, шрифты, все inline-стили одним источником правды
├── storage.js            — CloudStorage / localStorage адаптер
├── App.jsx               — главный компонент: состояние, бизнес-логика, разметка экрана
└── components/
    ├── Ui.jsx              — мелкие переиспользуемые поля форм (Field, InlineAdd, PsychRow)
    ├── ContactCard.jsx      — карточка контакта, обёрнута в React.memo
    ├── AiAssistantModal.jsx — AI-помощник, грузится лениво (React.lazy)
    ├── ImportModal.jsx      — импорт CSV, грузится лениво (React.lazy)
    ├── QuickAddAI.jsx        — быстрое добавление через AI/голос, лениво (React.lazy)
    ├── TaskBoard.jsx         — Kanban-доска задач по контактам, лениво (React.lazy)
    ├── HealthCheck.jsx       — оценка окружения, лениво (React.lazy)
    ├── Goals.jsx             — цели, лениво (React.lazy)
    └── Profile.jsx           — личный кабинет / тарифы, лениво (React.lazy)
```

Что сделано:

- **React.memo на карточках контактов** (`ContactCard.jsx`) — при выделении/групповом
  редактировании перерисовываются только реально изменившиеся карточки, а не весь список.
  Клик по карточке передаётся через `useCallback`, чтобы memo не ломался на каждом рендере.
- **CSS-виртуализация** вместо `react-window` — `content-visibility: auto` на карточках.
  Для сетки с переносом строк (как у нас) это работает надёжнее классических
  windowing-библиотек, которые рассчитаны на списки с фиксированной высотой строки.
  Если база вырастет до многих тысяч контактов — тогда уже можно рассмотреть react-window.
- **GPU-анимации** — все анимации используют только `transform`/`opacity`
  (это уже было так изначально) + добавлен `will-change`, чтобы браузер заранее
  промоутил слои в композитор.
- **Lazy-loading** — AI-помощник и импорт CSV подгружаются отдельными чанками
  через `React.lazy()` + `Suspense`, только в момент открытия. Первая загрузка
  приложения не тянет их код.



- **Хранилище (CloudStorage)**: у Telegram есть лимит — 4096 символов на
  один ключ и максимум 1024 ключа на пользователя. Наш `storage.js` уже
  разбивает большие данные на кусочки автоматически, так что для обычного
  использования (десятки-сотни контактов) хватит с запасом. Если база
  вырастет до тысяч контактов с фото — стоит перейти на настоящую БД
  (например, Supabase — бесплатный тариф вполне подойдёт).
- **Фото профиля**: хранятся как есть внутри контакта (base64), тоже
  через чанкованное CloudStorage — работает, но если фото много и они
  крупные, может потребоваться Supabase/Firebase Storage вместо
  CloudStorage для самих картинок.
- **AI-помощник**: требует backend-прокси (см. шаг 2). Без него всё
  остальное приложение работает нормально.

## Умное добавление через AI (Модуль 3A)

Второй, фиолетовый FAB (иконка "волшебная палочка") открывает виджет
`QuickAddAI` — можно надиктовать или напечатать свободный текст вроде:

> «Познакомился с Игорем на конференции. Он SEO-специалист, любит хайкинг,
> обещал скинуть чек-лист по аудиту к пятнице»

AI (через тот же backend-прокси, что и AI-поиск) раскладывает это на
структурированные поля — имя, категория, теги, профессия, интересы,
заметка — и, если в тексте есть договорённость или обещание, предлагает
создать связанную задачу (`follow_up` / `promise` / `intro`) со сроком.
Перед сохранением всё показывается на экран-превью, где можно
поправить любое поле или отменить задачу — ничего не сохраняется вслепую.

Голосовой ввод — через Web Speech API браузера (`SpeechRecognition`).
Поддержка: Chrome/Android — да, Safari/iOS — ограниченно или нет.
Если API недоступен, кнопка микрофона не показывается и остаётся обычный
текстовый ввод — деградация без поломки фичи.

Задачи сохраняются в отдельном ключе хранилища `fp_tasks` (та же
чанкованная схема, что и контакты) — это же хранилище использует будущий
Таск-борд (Модуль 3B).

## Таск-борд (Модуль 3B)

Кнопка со счётчиком в шапке (иконка списка) открывает `TaskBoard` —
полноэкранная Kanban-доска с тремя колонками: **К выполнению → В процессе →
Готово**. Колонки листаются свайпом по горизонтали (удобно на телефоне,
без drag-and-drop — на мобильном он ненадёжен, вместо этого на карточке
задачи есть кнопки ← / → для перемещения между колонками).

Каждая карточка задачи строго привязана к контакту (`task.contactId`) —
показывает его аватар и имя, тап по ним открывает карточку контакта.
Тип задачи (`Follow-up` / `Обещание` / `Интро`) — цветной бейдж, срок —
подсвечивается красным, если просрочен.

Задачи создаются двумя путями:
1. Автоматически — через AI quick-add (Модуль 3A), если в тексте есть договорённость
2. Вручную — кнопка «+ Задача» в шапке доски: выбор контакта из поиска, тип, текст, срок

Все задачи живут в `fp_tasks` (то же чанкованное хранилище, что и контакты).

## Умный анализ окружения (Модуль 3C)

Иконка-манометр (Gauge) в шапке открывает `HealthCheck` — оценку окружения
от 0 до 100 по трём критериям:

- **Разнообразие сфер** — сколько из заведённых пользователем категорий реально используются
- **Активность связей** — доля контактов с датой последнего контакта в пределах 90 дней
  (поле «Последний контакт» в психологическом портрете)
- **Глубина профилей** — доля контактов с заметками, интересами или заполненным портретом

Важное архитектурное решение: **сама арифметика (проценты, счётчики, дни)
считается в коде, детерминированно** (`computeHealthMetrics` в `helpers.js`),
а не отдаётся на откуп языковой модели — числам с плавающей точкой лучше
доверять калькулятору, а не генеративной модели. AI (через тот же
backend-прокси) используется только для того, чтобы облечь уже посчитанные,
точные факты в 3 конкретные рекомендации на человеческом языке — модели
явно передаются готовые цифры и запрещается их пересчитывать.

Если AI-прокси не настроен — экран всё равно полностью рабочий: цифры,
шкалы и разбивка по категориям считаются локально и показываются всегда,
только сами текстовые рекомендации в этом случае не подгрузятся (и это
видно пользователю честной подписью, а не тихо ломается).

## Цели и Личный кабинет (Модуль 3D)

**Цели** (иконка мишени в шапке) — два типа:
- Количественные — считаются автоматически по категории или тегу
  (например «10 контактов с тегом #ИИ»), либо вручную
- Качественные — просто отмечаются как выполненные/невыполненные

Прогресс — **чистая функция от текущих контактов** (`computeGoalProgress`
в `helpers.js`), а не число, которое хранится и может отстать от
реальной базы. На главном экране под категориями показывается компактная
полоска прогресса по ближайшей активной цели.

**Личный кабинет** (иконка карты) показывает тариф — Free Trial (лимит
AI-запросов в месяц) или Pro Networker — и расход лимита. Лимит реально
работает: AI-поиск, быстрое добавление и анализ окружения при исчерпанном
лимите показывают экран с призывом открыть кабинет вместо запроса к AI,
не прожигая деньги на API впустую.

**Про оплату — важно и честно**: реального приёма платежей здесь нет.
Кнопка «Оформить подписку» с выбором способа (Карта / СБП) — это
заготовка интерфейса; при нажатии показывается прямое объяснение, что
нужна интеграция с платёжным провайдером (ЮKassa, CloudPayments, Stripe
и т.п.) и backend, который подтверждает оплату и обновляет статус
подписки на сервере — это отдельная задача, не поднимается одним фронтендом.
Рядом есть **демо-переключатель** «Включить Pro в демо-режиме» — чисто
для локального тестирования интерфейса Pro-плана, явно подписан как
демо, ничего не оплачивает.
